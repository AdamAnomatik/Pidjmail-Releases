## Русский

Не публикуйте технические детали уязвимости или реальные данные в обычном GitHub Issue.

1. Откройте вкладку **Security** репозитория.
2. Используйте **Report a vulnerability**, если функция доступна.
3. Укажите версию Pidjmail и Windows, условия, безопасные шаги воспроизведения и возможное воздействие.

Если приватная отправка недоступна, создайте краткое обращение без технических подробностей и запросите приватный канал связи. Не прикладывайте пароли, ключи, файлы профиля, настоящую переписку или вредоносные вложения. Просим согласовать раскрытие подробностей после исправления.

## English

Do not publish vulnerability details or real user data in an ordinary GitHub Issue.

1. Open the repository's **Security** tab.
2. Use **Report a vulnerability** when available.
3. Include Pidjmail and Windows versions, preconditions, safe reproduction steps and potential impact.

If private reporting is unavailable, open a brief issue without technical details and ask for a private communication channel. Do not attach passwords, API keys, profiles, actual correspondence or malicious attachments. Please coordinate disclosure after a fix.

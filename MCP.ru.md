# Управление Pidjmail через MCP

В 0.2.8 есть локальный MCP-сервер и отдельный процесс stdio. Они работают, пока Pidjmail открыт, в том числе в трее. Node.js пользователю не нужен: процесс использует установленный Electron. MCP выключен по умолчанию и недоступен в демонстрации.

## Включение

1. Выйдите из демонстрации. Откройте **Настройки → ChatGPT и Claude → Управление через MCP**.
2. При необходимости выберите свободный порт; стандартный — 37861.
3. Включите **Разрешить MCP-подключение**. Должно появиться «MCP работает локально».
4. Нажмите **Экспортировать конфигурацию MCP** и сохраните JSON в свою закрытую папку.

Файл содержит отдельный ключ доступа MCP. Не вставляйте его содержимое в разговор с ИИ, issue или публичный репозиторий. Это не пароль почты, но файл разрешает доступ к поддерживаемым данным приложения. В самом профиле ключ зашифрован. Отключение MCP отзывает ключ; после повторного включения нужен новый экспорт. При переносе установки обновите конфигурацию: в ней абсолютный путь программы.

## Claude Desktop на Windows

Откройте конфигурацию локальных MCP-серверов Claude Desktop. Если используется `claude_desktop_config.json`, она расположена в `%APPDATA%\Claude\`. Объедините экспортированный объект `mcpServers.pidjmail` с имеющимися серверами, сохранив остальные записи, затем перезапустите Claude. В установленной программе должны появиться инструменты Pidjmail. Настройка может зависеть от версии клиента и политики организации. [Официальная инструкция Claude](https://support.claude.com/en/articles/10949351-getting-started-with-local-mcp-servers-on-claude-desktop).

## ChatGPT Desktop

Для локального MCP используется desktop-only plugin в локальном режиме чата. Экспортированный объект сервера содержит `type: stdio`, `command`, `args` и `env`. Это конфигурация сервера, а не готовый опубликованный плагин.

Для частного локального плагина создайте папку с `plugin.json` и `mcp.json`. В `mcp.json` поместите экспорт и поле `$schema: https://agent-plugins.org/schemas/1.0.0/mcp.schema.json`. Минимальный `plugin.json`:

```json
{
  "$schema": "https://agent-plugins.org/schemas/1.0.0/plugin.schema.json",
  "name": "pidjmail-local",
  "version": "0.2.8",
  "description": "Управление локальным Pidjmail"
}
```

Добавьте папку в личный локальный marketplace и установите плагин через каталог настольного клиента. Точные правила регистрации и путей приведены в [OpenAI Docs: локальный плагин](https://developers.openai.com/plugins/build/plugins#install-a-local-plugin-manually) и [desktop-only MCP](https://developers.openai.com/plugins/deploy/desktop-only). Доступность зависит от режима клиента и учётной записи. Установка плагина в вашем аккаунте автоматически не выполняется.

## Проверка после подключения

Попросите ИИ: «Используй Pidjmail, покажи мои почтовые аккаунты». Затем: «Найди письма по теме … и подготовь черновик ответа, не отправляй». Для проверки отправки запросите отправку черновика и **отклоните** запрос в Pidjmail: исходящие должны остаться без нового письма.

| Возможность                               | Инструменты                                     |
| ----------------------------------------- | ----------------------------------------------- |
| Аккаунты, поиск в кэше и чтение           | `list_accounts`, `search_mail`, `read_mail`     |
| Контакты, календарь, доски                | `list_contacts`, `list_calendar`, `list_boards` |
| Черновики без отправки                    | `list_drafts`, `create_draft`                   |
| Новые события и задачи                    | `create_event`, `create_task`                   |
| Запрос отправки или перемещения в корзину | `request_send_draft`, `request_trash_mail`      |
| Состояние запроса                         | `action_status`                                 |

Отправка и корзина требуют нажатия **Подтвердить действие** в окне MCP самого Pidjmail. Письмо проверяется целиком: адресаты, текст, вложения; изменение черновика после запроса блокирует отправку. `pending` означает ожидание, `queued`/«Добавлено в исходящие» — очередь, а не подтверждённую доставку. Письмо с неоднозначным результатом SMTP не отправляется автоматически повторно. Запросы живут в памяти десять минут; после перезапуска неподтверждённые действия не повторяются.

Поиск использует загруженный кэш. ИИ получает содержимое запрошенных писем и локальные данные; пароли, ключи других сервисов, вложения в исходном виде, команды оболочки и файловая система через инструменты не выдаются. Письма считаются недоверенными данными, а не инструкциями для управления приложением.

## ChatGPT и Claude в браузере

По вашему выбору в этой версии подготовлены локальное подключение и эта инструкция. **Внешний адрес не настроен.** Вкладка браузера не получает доступ к localhost просто по включению MCP.

Варианты дальнейшего подключения:

1. Для ChatGPT — поддерживаемый Secure MCP Tunnel к локальному stdio-серверу. Используйте команду/аргументы/окружение из экспорта в конфигурации туннеля, затем зарегистрируйте туннель в своём аккаунте. [OpenAI Docs: подключение и тестирование](https://developers.openai.com/plugins/deploy/connect-chatgpt).
2. Для общего HTTPS-доступа ChatGPT и Claude — отдельно развёрнутый MCP-шлюз с авторизацией, разрешением конкретного пользователя и защищённым каналом до этого ПК. Нужны адрес, сервер/туннель и настройка доступа. [Официальная инструкция Claude для удалённого MCP](https://support.claude.com/en/articles/11175166-get-started-with-custom-connectors-using-remote-mcp).

Текущий сервер слушает только `127.0.0.1`, требует отдельный bearer-ключ и отклоняет браузерные Origin. Он не является готовым публичным OAuth-сервером. Не делайте проброс его порта в интернет и не выбирайте No authentication для публичной почтовой интеграции. При настройке внешнего шлюза необходимо отдельно проверить авторизацию, отзыв доступа и сохранение подтверждений внутри Pidjmail.

В 0.2.8 проверены протокол, экспорт и запуск stdio-процесса из собранного/установленного приложения и отклонение отправки. Подключение в личных аккаунтах ChatGPT/Claude и работа через внешний туннель пока не проверялись.

## Встроенный помощник 0.2.14

Для работы с почтой прямо в боковом чате подключите API-ключ и модель в настройках AI. При включённом «Доступ к Pidjmail» помощник ищет и читает почту, смотрит контакты/календарь/доски и создаёт локальные черновики, события и задачи. Созданный черновик открывается по кнопке; письмо отправляете вы. Нужные данные передаются выбранному сервису по вашему запросу, API может оплачиваться отдельно. Поиск работает по загруженному кэшу.

Включение внешнего MCP для этого API-режима не требуется. Веб-вход ChatGPT/Claude остаётся отдельным режимом и сам по себе не подключает локальную почту: для него нужен MCP по инструкции выше. Браузерный шлюз автоматически не создаётся.
